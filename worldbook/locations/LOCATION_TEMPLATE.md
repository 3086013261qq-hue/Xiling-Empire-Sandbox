# 《希灵帝国》正式地点条目模板 v1.1

> 用途：P0/P1/P2正式地点正文统一格式。  
> 格式来源：严格服从《咩咩制卡·全栈》原生 `lore-place` 地点格式。  
> 原则：一个可复用的大地点默认对应一个地点条目；内部区域只有在需要独立地点触发、能够反复独立支撑场景时才另拆。

```text
<地点:正式名称>
介绍:地点客观描述。由外及里写稳定空间、环境、建筑/区域、长期社会与功能特征；若地点形态随时间变化，在同一个“介绍”字段内按原著先后说明状态变化，并服从正式时间线，不把后期状态倒灌到前期。
</地点:正式名称>
```

## 硬规则

1. 正式运行正文只使用 `<地点:名称> ... </地点:名称>` 根标签与 `介绍:` 入口字段，不自造 `<地点名location>`、`<身份>`、`<时间状态锁>` 等额外 schema。
2. 同一地点的空间、交通、居民、管理、功能、时代变化都作为“介绍”的组成内容，不因此拆成多个世界书条目。
3. 只有具备独立稳定场景身份、需要单独 `当前位置:` 触发的子地点，才允许另立地点条目；一次性舱室、街巷、战场、临时设施默认并入父地点。
4. 地点正文采用照相机式客观描述，不绑定“玩家来到这里必然发生某剧情”，不复制人物/能力正文，也不复述整段时间线。
5. 时间变化按原著事件顺序写入同一介绍；最终运行时由当前正式时间线约束可用状态。
6. 原著无专名但确需独立收录者，目录名必须显式标记 `【描述性目录名，原著无专名】`，不得伪装成官方地名。
7. 正式装配时地点属于全栈地点分区（order 100~1、触发型、after_char），主要扫描 `<status>` 中 `当前位置:`；源码阶段只维护地点正文与候选触发名，装配元数据统一在最终 assembly/manifest 处理。
8. 原著证据链、章节统计、层级争议与QA全部留在 `qa/**`，不塞入运行正文。
