# 《希灵帝国》正式地点条目模板 v1.0

> 用途：P0/P1/P2正式地点条目的统一正文骨架。  
> 原则：原著优先、时间线锁定、父子层级清晰、可直接支撑场景生成、避免重复时间线正文。

```xml
<地点名location>
<身份>
名称: 原著正式名称
别称: 仅收录原著明确使用的别称；称号与正式名分开
优先级: P0 / P1 / P2
类型: 世界 / 星球 / 城市 / 区域 / 设施 / 长期移动空间
空间归属: 写明父地点与空间层级；不得把父地点、城市和行政概念混成同义词
</身份>

<核心定位>
用2～4句说明该地点为什么值得独立成条：稳定场景身份、长期功能、势力/文明关系、环境规则。
只写地点自身，不复述人物设定、能力正文或整段时间线事件。
</核心定位>

<空间与环境>
- 稳定视觉与空间特征。
- 必要的气候、生态、重力、昼夜、人工环境规则。
- 只保留能影响场景生成的子区域；信息不足的P2候选并入此处。
</空间与环境>

<出入与交通>
- 常规入口、通行方式与权限边界。
- 军事/机密/危险区域与民用区域分开。
- 若出入规则随剧情变化，具体变化放入“时间状态锁”。
</出入与交通>

<居民与管理>
- 常驻居民类型、访客类型与稳定社会关系。
- 管理者、管理机构及其权限边界。
- 人物只做交叉引用，不重写人物条目。
</居民与管理>

<稳定功能>
- 只列跨阶段持续成立或在成熟阶段稳定存在的地点功能。
</稳定功能>

<时间状态锁>
阶段A｜第X～Y章:
- 仅写这一阶段已经成立的状态。
阶段B｜第Y+1～Z章:
- 只写新增、拆除、迁移、重建、归属或功能变化。
……
时态规则:
- 当前剧情存在卷/章/日期锚点时，只能调用不晚于该锚点的地点状态。
- 未给出明确锚点时，以当前会话已经发生的最新正式时间线节点为准。
- 禁止用后期建筑、人口、称号、交通权限、毁坏/重建结果反向覆盖前期。
</时间状态锁>

<场景生成锚点>
- 列出最稳定的感官、空间、社会与行动锚点。
- 不把一次性剧情事件写成永久环境。
- 原著无专名的子地点只使用描述性称呼，并标记“原著无专名”。
</场景生成锚点>

<交叉引用>
设定: 仅列相关冻结设定名
人物: 仅列相关冻结人物名
能力: 仅在地点规则确实依赖能力时引用
地点: 仅列父地点、稳定邻接地点或未来独立条目
时间线: 列卷/章锚点，不复制时间线正文
</交叉引用>

<原著核验锚点>
列出用于复核的关键章节号与章名；不摘抄大段原文。
</原著核验锚点>
</地点名location>
```

## 模板硬规则

1. “地点身份”与“阶段状态”分离；任何会变化的内容优先进入时间状态锁。
2. 别称、称号、父地点、行政概念必须分栏，禁止为了关键词触发而错误合并。
3. 子地点只有在可独立支撑场景或需要独立触发时才拆条；否则留在父地点的空间结构中。
4. 触发词与正式装配元数据在地点层总审时统一去重；生产正文不为凑关键词制造新地名。
5. 世界书运行正文控制体积；证据链、统计、长篇核验全部放入 `qa/**`。
